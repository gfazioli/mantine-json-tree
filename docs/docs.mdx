## What's new

- **Structural editing** — rename keys, add and remove keys and items, reorder arrays (`structuralEdits`)
- **Entry limit** — long objects and arrays end with a "… N more" row that reveals the next page (`maxDisplayLength`)
- **Locked expansion** — every node open, none can be collapsed (`allExpanded`)
- **Quote style** — show or hide the quotes around strings and keys (`withQuotes`, `withKeyQuotes`)
- **Labels** — translate every built-in string, and every icon button now has an accessible name (`labels`)
- **Indentation width** (`indentWidth`) and a root without a label (`rootName={false}`)
- **Diff highlighting** — mark nodes as added, removed or changed (`highlightNode`)
- **Large arrays** split into collapsible `[start…end]` groups (`groupArraysAfterLength`)
- **Long strings** cut with a "show more" toggle (`collapseStringsAfterLength`)
- **Type badges** next to every value (`showValueTypes`)
- **Sorted keys**, alphabetical or with your own comparator (`sortKeys`)
- **Editable values** — click a string, number or boolean to edit it in place (`editable`, `onChange`)
- **Circular references** are detected and marked instead of crashing the component
- **Search** with text highlight, auto-expand, and filtered tree view (`withSearch`)
- **Redesigned toolbar** with key count badge, global copy, search toggle, and modern icons
- **Paper wrapper** with `withBorder` for bordered container look
- **Root name** customization (`rootName` prop)
- **Global copy** button to copy entire JSON to clipboard (`withCopyAll`)
- **Key count badge** showing total keys/items next to title (`withKeyCountBadge`)
- Dark mode support with automatic color adaptation
- Line numbers display (`showLineNumbers`)
- Path tooltip on hover (`showPathOnHover`)
- Max height with scrollable container (`maxHeight`)
- Controlled expand/collapse state (`expanded`, `onExpandedChange`)
- `onExpand` and `onCollapse` callbacks for individual node toggling
- Keyboard copy: `Ctrl+C` / `Cmd+C` copies the focused node when `withCopyToClipboard` is enabled
- Responsive `size` prop via Mantine breakpoint objects (CSS-native, no re-renders)

**When to use which.** Reach for `JsonViewer` for a light, read-only view of JSON that came over the wire, especially if you already use `@mantine/code-highlight`. Reach for `JsonTree` when the data is a live JavaScript value — Dates, Maps, Sets, functions, circular graphs — when you need to search it, or to edit it in place, values and structure alike, or when the tree is a tool of its own, with a title, a sticky toolbar and indent guides.

## Usage

The `JsonTree` is interactive JSON tree viewer component built with [Mantine's Tree component](https://mantine.dev/core/tree/). Features collapsible nodes, syntax highlighting with type-specific colors, copy-to-clipboard functionality, item count badges, configurable expansion depth, and smooth animations. Perfect for debugging API responses, exploring complex data structures, and developer tools.

## Editing Values

Set `editable` to let a reader change a value in place. Click a string or a number to open an
inline editor — `Enter` commits, `Escape` cancels, moving focus commits — or click a boolean to
toggle it outright, since it has exactly one other state. With a row focused, `Enter`
opens its editor too, so the whole flow works from the keyboard without adding a tab stop per value.

`JsonTree` is **controlled** while editing: it never keeps its own copy of your data. `onChange`
hands you the next value, and it only takes effect once you feed it back through `data`.

`data` is typed `unknown`, so `onChange` hands the next value back as `unknown` too. Editing a
value never changes the shape of the object — a string stays a string, a number a number — so
casting it back to your own type is safe:

```tsx
const [data, setData] = useState<Profile>(initial);

<JsonTree data={data} editable onChange={(next) => setData(next as Profile)} />
```

The original object is never mutated. Only the spine down to the edited node is rebuilt, so every
`Date`, `Map`, `Set`, `RegExp`, `BigInt`, function and React element elsewhere in the tree keeps
its identity — a `structuredClone` or a JSON round-trip would flatten or destroy all of them.

<Demo data={demos.editable} />

### What can be edited

`editableTypes` defaults to `['string', 'number', 'boolean']`; anything outside it stays read-only.
Two kinds of node can never be edited, whatever you put in that list:

- **`Map` and `Set` entries.** They are displayed under a synthetic key — a `Map` key can be any
  value at all, including an object — so there is no address to write back to.
- **Function properties expanded with `displayFunctions="as-object"`.** Those properties belong to
  a synthetic object that does not exist in your data.

`isEditable` gates individual nodes, and `validate` rejects a value by returning a message:

```tsx
<JsonTree
  data={data}
  editable
  onChange={setData}
  isEditable={({ path }) => path !== 'root.id'}
  validate={({ value }) => (String(value).trim() === '' ? 'Cannot be empty' : null)}
/>
```

### Addressing a node

`onChange` receives a change object carrying both ways of naming the node:

- `path` — the display label, e.g. `root.address.city`. It is **not unique**: `{ 'a.b': 1 }` and
  `{ a: { b: 1 } }` both produce `root.a.b`, and an array index reads the same as a numeric object
  key.
- `pathSegments` — the real address, one step per level, with object keys as strings and array
  indices as numbers. This is what the write is performed against, so an edit always lands on the
  node you clicked.

Use `path` for display and logging; use `pathSegments` whenever you need to act on the node.

## Editing Structure

Add `structuralEdits` to `editable` and the reader can change the shape of the data too: rename
an object key, add a key or an item, remove one, and move the items of an array. Pass `true` for
all four, or a list such as `['add', 'remove']` for some of them.

- **Rename**: click a key, or press `F2` on its row, and type the new name. A key the object
  already has is refused, and `validateKey` can refuse others.
- **Add**: the `+` button on an object asks for the new key; on an array it appends an item. A new
  entry starts with the type of the container's last entry, emptied (`''`, `0`, `false`, `null`,
  `{}`, `[]`), or with whatever `getNewValue` returns; a new string or number opens its editor at
  once.
- **Remove**: the bin button, or `Delete` / `Backspace` on the focused row.
- **Reorder**: the arrow buttons on an array item, or `Alt + ↑ / ↓`.

<Demo data={demos.structural} />

`onChange` reports each change with an `action` — `'edit'` for a value, or `'rename'`, `'add'`,
`'remove'` and `'reorder'` — and a rename or a reorder also carries `previousPath`,
`previousPathSegments` and `previousKey`. Every write goes through `pathSegments`, so it lands on
the node you meant even when two keys share a display path, and, as with values, only the spine
down to the change is rebuilt.

Keys and indices are part of every path below them, so a rename or a shifted index changes the
path of a whole subtree. `JsonTree` carries its own state across: expanded nodes stay expanded
under their new paths (a controlled `expanded` gets the new list through `onExpandedChange`),
revealed pages stay revealed, and focus follows the change — to the renamed row, the moved item,
or the entry that took a removed one's place. The same entries as for values stay read-only:
`Map` and `Set` entries, the `[start…end]` groups, reference cycles, and whatever `isEditable`
refuses.

## Search

Enable `withSearch` to add a search toggle in the toolbar.
When active, the tree filters to show only branches with
matching keys or values. Direct matches get an amber
background highlight, and the matching text portion is
highlighted inline. Parent nodes are preserved for context.
Clearing the search restores the previous expand state.

## Copy to Clipboard

Both per-node and global copy buttons provide visual feedback — the icon briefly changes to a green
checkmark after a successful copy.

The **global copy** button (`withCopyAll`) copies the raw JSON data without the `rootName` wrapper.
The `rootName` is a display-only label and is not included in the copied output. This makes the
copied JSON directly usable in code and API tools.

What lands on the clipboard is what the tree shows. `JSON.stringify` alone cannot express
everything the tree renders — it returns `undefined` for functions, symbols and `undefined`, and
throws on `BigInt` and on any value holding a reference cycle — so those fall back to the rendered
form rather than copying the literal text `undefined` or silently doing nothing.

## Root Name

Use the `rootName` prop to customize the label of the
root node. Defaults to `"root"`. This is useful for API
responses, config files, or when displaying multiple
trees with different root labels. Note that `rootName`
is display-only — it does not affect the copied JSON
output. Pass `rootName={false}` to show the root without a label;
paths keep their `root` prefix, so `expanded`, `onNodeClick` and
the path tooltip are the same either way:

## Quote Style

Strings are shown between quotes and object keys without them, as Mantine's `JsonViewer` does by
default. `withQuotes={false}` drops the quotes around strings, and `withKeyQuotes` adds them
around object keys — never around an array index, a `Map` or `Set` entry or a group label, which
JSON would not quote either. Search matches the text as it is displayed, and copying still
produces valid JSON.

## Special Value Types

`JsonTree` supports modern JavaScript types beyond standard JSON primitives. These include Date objects, special numeric values (NaN, Infinity), BigInt for large integers, Symbols, RegExp patterns, and ES6 collections like Map and Set. Each type is displayed with distinct syntax highlighting and formatting:

- **Date**: Displayed in ISO 8601 format (e.g., `2024-01-15T10:30:00.000Z`)
- **NaN / Infinity**: Special numeric values shown with their standard JavaScript representation
- **BigInt**: Large integers displayed with the `n` suffix (e.g., `9007199254740991n`)
- **Symbol**: Unique identifiers shown with their description (e.g., `Symbol(unique)`)
- **RegExp**: Regular expressions displayed with their pattern and flags (e.g., `/pattern/gi`)
- **Map**: Key-value collections that are expandable to show their entries
- **Set**: Unique value collections that are expandable to show their elements
- **React Elements**: React components displayed with their component name (e.g., `<Loader />`)

React elements are recognised by their internal `$$typeof` marker, so ordinary data is never
mistaken for one. An object such as `{ type: 'text', props: { label: 'Name' } }` — a common
shape in form-builder and low-code JSON — is rendered as a regular, expandable object.

All colors can be customized using CSS variables for each type.

## Circular References

Object graphs that point back at themselves are everywhere in real debugging sessions — a child
holding a reference to its parent, a linked list, a cached entity pointing at the store that owns
it. `JsonTree` walks the current branch and stops as soon as a value reappears on its own ancestor
chain, rendering it as `[Circular]` rather than recursing until the stack overflows.

Only the ancestor chain is tracked, never every value already visited. A value referenced from two
different branches is shared, not circular, so it keeps expanding normally in both places — as the
`config` object does below.

## Diff Highlighting

`highlightNode` is called for every node except the synthetic `[start…end]` groups of `groupArraysAfterLength`, and returns how it changed: `'added'`, `'removed'`, `'changed'`, or `null` to leave it as is. It receives the node's `path`, `pathSegments`, `key`, `type` and `value`, so a diff can be computed against any previous version of the data — below, by reading the same `pathSegments` in both versions.

The colors come from the `--json-tree-highlight-added-color`, `--json-tree-highlight-removed-color` and `--json-tree-highlight-changed-color` variables, and each highlighted row carries a `data-json-tree-highlight` attribute for your own styles.

<Demo data={demos.diff} />

## Large Data

Three props keep big payloads readable:

- `groupArraysAfterLength` splits an array longer than the given length into collapsible `[start…end]` groups of that many items, so a large array does not render every item at once. Each group is one more level of the tree (and of `maxDepth`); the items inside keep their own paths, so search, copy and editing work as before.
- `collapseStringsAfterLength` cuts longer strings and adds a "show more" toggle. While a search is active the whole string is shown, so a match past the cut stays visible.
- `showValueTypes` adds a type badge next to every value: `string`, `int`, `float`, `bool`, `null`, `object`, `array`, `date` and so on.

<Demo data={demos.largeData} />

### Entry limit

`maxDisplayLength` shows at most that many entries of an object, array, `Map` or `Set`, and closes
it with a "… N more items" row. That row is a button: a click, or `Enter` on the focused row,
reveals the next as many entries and moves focus to the first of them. An array split by
`groupArraysAfterLength` is left whole, and the limit is off while a search is active, so no match
hides behind it. Copy, search, expand all and the key count badge always work on the full value.

<Demo data={demos.entryLimit} />

## Sort Keys

Set `sortKeys` to show object keys in alphabetical order, or pass a comparator such as `(a, b) => b.localeCompare(a)`. Arrays keep their order, and so does the data: sorting only changes what is displayed, so paths and edits are unaffected. Memoize a comparator, since a new function on every render rebuilds the tree.

You can customize the expand/collapse icons used in the `JsonTree` component by providing your own icons via the `expandControlIcon` and `collapseControlIcon` props. The default icons are simple chevrons, but you can replace them with any React component or icon of your choice.

## Function Display

By default, functions in JSON data are displayed as strings (e.g., `[Function: name]`). You can control how functions are handled using the `displayFunctions` prop:

- `as-string` (default): Display functions as formatted strings showing their name
- `hide`: Completely omit functions from the tree
- `as-object`: Treat functions as objects and display their properties

## Keyboard Navigation

`JsonTree` inherits full keyboard navigation from Mantine's Tree component:

- **Arrow Up/Down**: Navigate between nodes
- **Arrow Right**: Expand a collapsed node or move to first child
- **Arrow Left**: Collapse an expanded node or move to parent (with `allExpanded`, always move to
  the parent)
- **Space**: Toggle node expansion
- **Enter**: Open the inline editor for the focused row (when `editable` is enabled). Editable
  values add no tab stop of their own, so a large tree stays one stop, as Mantine's Tree intends
- **Ctrl+C / Cmd+C**: Copy the focused node's value to clipboard (when `withCopyToClipboard` is
  enabled). With no node focused it falls back to the root, and it never intercepts the shortcut
  while a form control inside the component — such as the search input — holds focus.
- **Enter** on a "… N more items" row: reveal the next entries (`maxDisplayLength`)
- With `structuralEdits`: **F2** renames the focused key, **Delete** / **Backspace** removes the
  focused row, **Insert** / **+** adds to it, and **Alt + Arrow Up/Down** moves an array item

## Labels and Accessibility

Every string `JsonTree` renders or announces on its own comes from `labels`, so a tree can be translated without touching the component. Pass only the ones to change; the rest keep their English defaults.

The labels cover:
- **Icon buttons**: copy, copied, copy all, expand all, collapse all, search, add, remove, move up and move down. Every icon button carries its label as its accessible name, so a screen reader announces "Copy" rather than an unnamed button. The toolbar's buttons also show it as a tooltip.
- **Text on screen**: "show more" / "show less" and the "… N more items" row. `moreItems` is a function of the count and of the unit (`items`, `keys` or `entries`), for languages whose plurals follow different rules.
- **Inline editors**: the names of the new-key, rename and value inputs (`rename` and `edit` take the key), and their validation messages (`keyExists`, `required`, `notANumber`).

The search placeholder keeps its own prop, `searchPlaceholder`, and the key count badge its own `keyCountBadgeLabel`.

## Controlled Expand State

Use the `expanded` and `onExpandedChange` props for controlled expand/collapse state. The `onExpand` and `onCollapse` callbacks fire for individual node toggling:

```tsx
const [expanded, setExpanded] = useState<string[]>([
  'root',
  'root.settings',
]);

<JsonTree
  data={data}
  expanded={expanded}
  onExpandedChange={setExpanded}
  onExpand={(path) => console.log('Expanded:', path)}
  onCollapse={(path) => console.log('Collapsed:', path)}
/>;
```

## Locked Expansion

`allExpanded` opens every node, array groups included, and keeps them open: the toggles and the
expand/collapse all controls disappear, and neither the mouse nor the keyboard can collapse a
node. It suits a static payload in documentation or a report. `defaultExpanded`, `maxDepth` and a
controlled `expanded` are ignored while it is on.

## Responsive size

The `size` prop supports responsive values using Mantine breakpoint objects. This allows you to set different font sizes based on the viewport width, using CSS media queries (no JavaScript re-renders):

```tsx
<JsonTree data={data} size={{ base: 'xs', sm: 'sm', lg: 'md' }} />
```
